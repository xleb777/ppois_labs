# Лабораторная работа №1: вектор и множество

Реализованы оба выбранных варианта: вектор в трёхмерном пространстве (1.1) и канторовское множество (1.4.1) с общими операциями из пункта 1.4. Одно консольное приложение содержит два независимых подменю. Требования: [задание](https://github.com/alix-zzh/ppois-course/blob/master/ru/lab1.md), [общие требования](https://github.com/alix-zzh/ppois-course/blob/master/ru/common_requirements.md), [чеклист](https://github.com/alix-zzh/ppois-course/blob/master/ru/checklist.md).

## Сборка и запуск

### Windows x64

Для сборки из исходников установите [MSYS2](https://www.msys2.org/) и откройте именно терминал **MSYS2 UCRT64**. Перейдите в папку проекта (например, `cd /c/Users/YourName/Downloads/ppois-course`) и выполните:

```bash
pacman -S --needed make mingw-w64-ucrt-x86_64-gcc
make -C lab1 release
./lab1/build/release/lab1.exe
```

Для тестов добавьте [Catch2](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-catch) и `pkgconf` в том же терминале:

```bash
pacman -S --needed mingw-w64-ucrt-x86_64-pkgconf mingw-w64-ucrt-x86_64-catch
make -C lab1 test
```


### Что ввести в меню

- **Вектор**: выберите `1`, затем `1` и введите `1 2 3 3 2 3` для `A`. Выберите `2` и введите `0 0 0 0 1 0` для `B`. В пункте `6` векторное произведение будет записано как `1 2 3 1 2 5`: это точки начала и конца, а не только компоненты перемещения.
- **Множество**: выберите `2` в главном меню, затем `1` и введите `{a, b, {a, b}, {}, {b, a}}`. Пункт `3` покажет мощность `4`: `{a,b}` и `{b,a}` считаются одним вложенным элементом. В пункте `6` можно проверить принадлежность `{b,a}`, а пункт `10` построит булеан из 16 подмножеств.

`0` в подменю возвращает в главное меню, а `0` в главном меню завершает программу. Меню ограничивает показ булеана двенадцатью элементами, чтобы не печатать тысячи строк по ошибке; у метода `Set::powerSet()` такого ограничения нет.

## Как устроен код

- **`include/` и `src/`**: объявления классов находятся в `.h`, реализация в `.cpp`. `menu.cpp` работает через публичные методы и операции, а классы не используют `std::cin`, `std::cout` или меню.
- **`Vector3D`**: хранит две точки. Для вычислений берётся перемещение `конец − начало`. Начало результата совпадает с началом левого операнда. `==` точно сравнивает координаты обеих точек, а `<`, `<=`, `>` и `>=` сравнивают только длины. При делении на ноль или вычислении косинуса с нулевым вектором выбрасывается `std::domain_error`.
- **`Set`**: хранит уникальные элементы в `std::set<std::string>`. Слово хранится как есть, а вложенное множество как отсортированная запись в фигурных скобках. Поэтому `{a,b}` и `{b,a}` имеют одну внутреннюю запись. Сортировка нужна для воспроизводимой записи, а не для порядка элементов в математическом множестве. Слово не может содержать пробел, запятую или фигурную скобку.
- **Копирование и ресурсы**: оба класса используют конструктор копирования, присваивание и деструктор `= default`. Копирование значений не связывает оригинал с копией; память контейнера освобождается автоматически. Операция `>>` заменяет объект только после успешного чтения.
- **`tests/`**: тесты Catch2 проверяют оба класса, ошибки ввода и работу меню через строковые потоки.

### Три места, с которых удобно начать разбор

- **`Vector3D::operator*`**: для перемещений `(2, 0, 0)` и `(0, 1, 0)` получаем `(0, 0, 2)`. `withDisplacement()` прибавляет это перемещение к началу левого вектора. Если поменять сомножители местами, меняется знак результата.
- **`Set::readElement`**: встретив `{`, функция вызывает `readSet()` для вложенного множества. Тот разбирает элементы по тем же правилам и возвращает их в канонической записи. Проследите этот путь на примере `{a, {b,a}, {a,b}}`.
- **`Set::powerSet`**: начните с `{}` как единственного подмножества. Для `a` добавьте `{a}`; для `b` скопируйте два уже известных подмножества и добавьте в копии `b`. Получаются `{}`, `{a}`, `{b}`, `{a,b}`. На каждом шаге список удваивается, поэтому у множества из `n` элементов будет `2ⁿ` подмножеств.

## Проверки, документация и готовая сборка

Команды ниже приведены для Linux. На Windows можно собрать программу и запустить тесты нативно по инструкции выше, а отчёт о покрытии, Cppcheck и документацию проверяет Linux-задача в GitHub Actions.

```bash
make -C lab1 test       # тесты Catch2
make -C lab1 coverage   # тесты и контроль покрытия строк > 90%
make -C lab1 lint       # статический анализ Cppcheck
make -C lab1 docs       # документация Doxygen
make -C lab1 release    # автономный исполняемый файл для текущей платформы
```

Открывайте `lab1/build/docs/html/index.html` для документации и `lab1/build/coverage/report/index.html` для отчёта покрытия с подсветкой строк. При подсчёте покрытия берутся собственные `src/` и `include/`; сторонние библиотеки и код тестов в метрику не входят.

В GitHub Actions проверки запускаются для Pull Request и при попадании изменений в `main`. Windows-задача выполняет тесты Catch2 и проверяет запуск `lab1.exe` из PowerShell. После успешных проверок на `main` workflow публикует в Releases `lab1-windows-x86_64.zip`, `lab1-linux-x86_64.tar.gz`, документацию Doxygen и отчёт покрытия. Для запуска Linux-версии распакуйте архив командой `tar -xzf lab1-linux-x86_64.tar.gz` и запустите `./lab1` из папки распаковки.
